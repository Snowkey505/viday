# Таблица тестирования базы данных Viday

Схема: `viday`. Скрипты: `docker/postgres/init/`. СУБД: PostgreSQL 15.


| №                                    | Описание теста                               | Входные данные                                                                                               | Ожидаемый результат                                                                               |
| ------------------------------------ | -------------------------------------------- | ------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------- |
| **1. Справочники и PK**              |                                              |                                                                                                              |                                                                                                   |
| 1.1                                  | Первичный ключ `role`                        | `INSERT INTO viday.role (id, name) VALUES (1, 'GUEST')` повторно без `ON CONFLICT`                           | Ошибка `unique_violation` на PK                                                                   |
| 1.2                                  | Ссылка на справочник роли                    | `INSERT INTO viday."user" (username, password, role_id) VALUES ('t1', 'hash', 999)`                          | Ошибка FK: `role_id` не существует                                                                |
| **2. Уникальность**                  |                                              |                                                                                                              |                                                                                                   |
| 2.1                                  | Уникальный логин                             | Два `INSERT` пользователя с `username = 'same_user'`                                                         | Второй insert: `unique_violation` на `uk_user_username`                                           |
| 2.2                                  | Уникальная позиция в плейлисте               | Два `content_to_playlist` с одним `playlist_id` и `position = 1`                                             | Второй insert: `unique_violation` на `uk_content_to_playlist_position`                            |
| 2.3                                  | Один source variant                          | Два `media_variant` с `content_id=1`, `is_source=true`, разные id                                            | Второй insert/update: ошибка триггера `BUSINESS_RULE_VIOLATION` (один source)                     |
| 2.4                                  | Дубликат технических параметров variant      | Два variant с одинаковыми `(content_id, width, height, bitrate, codec_id)`                                   | `unique_violation` на `uk_media_variant_technical`                                                |
| **3. CHECK-ограничения**             |                                              |                                                                                                              |                                                                                                   |
| 3.1                                  | Ширина media_variant                         | `width = 0`                                                                                                  | Ошибка `chk_media_variant_width`                                                                  |
| 3.2                                  | Длительность видео                           | `duration_seconds = 0` в `video`                                                                             | Ошибка `chk_video_duration`                                                                       |
| 3.3                                  | Позиция в плейлисте                          | `position = 0` в `content_to_playlist`                                                                       | Ошибка `chk_content_to_playlist_position`                                                         |
| 3.4                                  | Подписка на себя                             | `user_follows`: `following_user_id = followed_user_id`                                                       | Ошибка `chk_user_follows_not_self`                                                                |
| **4. Триггер приватности плейлиста** |                                              |                                                                                                              |                                                                                                   |
| 4.1                                  | Приватный контент в публичный плейлист       | `content.access_type_id = 2` (PRIVATE), `playlist.access_type_id = 1` (PUBLIC), `INSERT content_to_playlist` | Ошибка `BUSINESS_RULE_VIOLATION` (триггер `trg_check_content_playlist_privacy_restrictions`)      |
| 4.2                                  | Контент для подписчиков в публичный плейлист | `content.access_type_id = 3`, `playlist.access_type_id = 1`                                                  | Та же ошибка триггера                                                                             |
| 4.3                                  | Публичный контент в публичный плейлист       | `access_type_id = 1` у обоих, валидная `position`                                                            | Запись успешна                                                                                    |
| **5. Триггер позиции плейлиста**     |                                              |                                                                                                              |                                                                                                   |
| 5.1                                  | Позиция «в конец»                            | Плейлист пустой, `position = 1`                                                                              | Успех                                                                                             |
| 5.2                                  | Позиция с пропуском                          | В плейлисте max `position = 2`, `INSERT position = 5`                                                        | Ошибка `BUSINESS_RULE_VIOLATION` (триггер `trg_validate_playlist_position`)                       |
| **6. Статистика просмотров**         |                                              |                                                                                                              |                                                                                                   |
| 6.1                                  | Инкремент просмотров                         | `INSERT INTO content_to_playlist (content_id, playlist_id, position) VALUES (X, …, 1)`                       | В `content_view_stats` для `content_id = X`: `view_count` +1, обновлён `last_viewed_at`           |
| 6.2                                  | Повторное добавление                         | Второй аналогичный сценарий для того же контента                                                             | `view_count` увеличен ещё на 1 (UPSERT)                                                           |
| **7. CASCADE удаления**              |                                              |                                                                                                              |                                                                                                   |
| 7.1                                  | Удаление пользователя                        | `DELETE FROM viday."user" WHERE id = owner_id`                                                               | Каскадно удалены его `content`, `playlist`, `user_follows`                                        |
| 7.2                                  | Удаление контента                            | `DELETE FROM viday.content WHERE id = ?`                                                                     | Каскадно удалены `video`, `stream`, `media_variant`, `content_view_stats`                         |
| **8. Row Level Security**            |                                              |                                                                                                              |                                                                                                   |
| 8.1                                  | Гость видит публичный контент                | Сессия `SET ROLE viday_guest`; `SET app.current_user_id` не требуется; `SELECT` из `content`                 | Только строки с `access_type_id = 1`                                                              |
| 8.2                                  | Пользователь видит свой приватный            | `SET ROLE viday_user`; `SET app.current_user_id = '5'`; контент с `owner_id=5`, `access_type_id=2`           | Строка видна                                                                                      |
| 8.3                                  | Пользователь не видит чужой приватный        | `app.current_user_id = 5`, контент `owner_id = 9`, private                                                   | Строка не возвращается                                                                            |
| **9. Роли PostgreSQL**               |                                              |                                                                                                              |                                                                                                   |
| 9.1                                  | Analyst читает статистику                    | Подключение `viday_analyst_user`; `SELECT * FROM viday.content_view_stats`                                   | Успех                                                                                             |
| 9.2                                  | Analyst не читает пароль                     | `SELECT password FROM viday."user"`                                                                          | Ошибка доступа (столбец не в GRANT)                                                               |
| 9.3                                  | Guest не удаляет плейлист                    | `SET ROLE viday_guest`; `DELETE FROM viday.playlist`                                                         | Ошибка прав                                                                                       |
| 9.4                                  | Admin полный доступ                          | `SET ROLE viday_admin`; `DELETE` произвольной записи                                                         | Успех (в рамках FK)                                                                               |
| **10. Индексы (производительность)** |                                              |                                                                                                              |                                                                                                   |
| 10.1                                 | Лента публичного контента с индексом         | Наполнение ≥10k `content`, `EXPLAIN ANALYZE` запрос из `research/01_index_performance_test.sql` с индексами  | План: `Index Scan` / `Bitmap Index Scan` на `idx_content_access_created`, время < sequential scan |
| 10.2                                 | Тот же запрос без индекса                    | `SET enable_indexscan = off`; тот же SELECT                                                                  | План: `Seq Scan`, время выше, чем в 10.1                                                          |
| 10.3                                 | Контент плейлиста                            | `EXPLAIN` JOIN `content_to_playlist` + `playlist_id = ?`                                                     | Использование `idx_content_to_playlist_position`                                                  |
| **11. API ↔ БД (интеграционные)**    |                                              |                                                                                                              |                                                                                                   |
| 11.1                                 | Регистрация USER                             | `POST /api/auth/register`                                                                                    | В БД `role.name = USER`                                                                           |
| 11.2                                 | Активация канала                             | USER → `POST /api/users/me/channel/activate` + refresh token                                                 | `role.name = CREATOR`                                                                             |
| 11.3                                 | Назначение аналитика                         | ADMIN → `POST .../promote-analyst`                                                                           | `role.name = ANALYST` у целевого пользователя                                                     |
| 11.4                                 | Админ удаляет чужой контент                  | ADMIN → `DELETE /api/admin/contents/{id}`                                                                    | Запись отсутствует в `content`, файлы сняты с хранилища                                           |
| 11.5                                 | Аналитик без прав админа                     | ANALYST → `DELETE /api/admin/users/1`                                                                        | HTTP 403                                                                                          |
| 11.6                                 | Аналитик читает статистику                   | ANALYST → `GET /api/analytics/views`                                                                         | HTTP 200, JSON из `content_view_stats`                                                            |


## Порядок прогона

1. `docker compose up -d postgres` — применятся `init/*.sql`.
2. Тесты 1–7, 9 — SQL в psql (`viday_admin_user`).
3. Тест 8 — отдельные сессии с `SET ROLE` / `SET app.current_user_id`.
4. Тест 10 — `make benchmark-db` или скрипты `docker/postgres/research/`.
5. Тест 11 — запущенное приложение + JWT по ролям (см. `[roles.md](roles.md)`).
